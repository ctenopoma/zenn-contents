列生成法は「**変数**が多すぎるから後から作る」手法でした。今回扱う**Benders分解**はその鏡写し——「**制約**(正確には別の判断に属する部分)を後から作る」手法です。3-3の遅延制約生成の、理論武装した親玉と言えます。

キーになるのは問題のこんな構造です。

> 難しい決定(整数)を**先に固定してしまえば、残りはただのLP**になる。

この構造を持つ問題は実務に山ほどあります。施設の配置を決めれば輸送はLP。設備投資を決めれば運用計画はLP。ネットワーク設計を決めればルーティングはLP。今回は施設配置+輸送を題材に、Benders分解をゼロから実装して、一括で解いたMIPと答え合わせします。

:::message
コードと数値はすべて手元で実行した実測です。
:::

## 題材:施設配置+輸送

- 施設候補10箇所(固定費3000〜7000円、能力60〜120個)
- 顧客25件(需要計528個)、輸送費は距離×個数
- どの施設を開き(0/1)、どこからどこへ運ぶか(連続)。総コスト最小

まず答え合わせ用に、一括のMIP(2-4の強い定式化)で解いておきます。

```text
一括MIP: 39429.4, 開設=[0, 4, 5, 7, 8]
```

## 分解の発想:2人の担当者に分ける

問題を2人に分けます。

- **マスター(経営者)**: どの施設を開くか $y$ を決める。輸送費は詳細を知らないので、**見積もり変数 $\eta$** で代用する
  $$\min \sum_i f_i y_i + \eta$$
- **サブ(物流部長)**: 経営者が決めた $\bar{y}$ を所与として、輸送計画を立てる。これは**ただの輸送LP**(3-1で見たネットワーク構造。一瞬で解ける)

最初、経営者の見積もり $\eta$ は根拠なしの0です。当然、開設費だけ安い配置を選んでしまう。そこで物流部長が実際に輸送LPを解き、**「その配置なら輸送費はこれだけかかります。しかも配置をこう変えたらこう変わります」という報告書**を返します。この報告書が**Bendersカット**です。

## カットの正体:双対価格の再登場

報告書の中身は、輸送LPの**双対価格**(1-4)です。

- 顧客 $j$ の需要制約の双対 $v_j$ =「顧客 $j$ の需要1個分の限界輸送費」
- 施設 $i$ の能力制約の双対 $u_i$ =「施設 $i$ の能力1個分の価値」(≤0。能力が増えると輸送費は下がる)

LPの強双対性(1-4)から、輸送費は $\sum_j d_j v_j + \sum_i \mathrm{cap}_i \bar{y}_i u_i$ と書けます。そしてこの式は、**双対解を固定したまま $y$ を動かしても「輸送費の下限」であり続けます**(双対解は $y$ が変わっても双対問題の実行可能解のままだから)。つまり:

$$\eta \ge \sum_j d_j v_j + \sum_i \mathrm{cap}_i\, u_i\, y_i$$

これが**最適性カット**。マスターに1本追加すると、経営者の見積もりが「その方向の楽観」を封じられます。あとはループです。

```python
for it in range(50):
    master.optimize()                       # 経営者: 配置と見積もりを決める
    ybar = [round(master.getVal(y[i])) for i in range(F)]
    sub_cost, v, u, _ = solve_sub(ybar)     # 物流部長: 輸送LPを解いて双対を返す
    ub = 開設費(ybar) + sub_cost            # 実際にやってみた総コスト → 上界
    lb = master.getObjVal()                 # 経営者の楽観見積もり     → 下界
    if ub - lb が十分小さい: break
    master.freeTransform()                  # SCIPで解いた後に制約を足すときの作法
    master.addCons(eta >= sum(dem[j]*v[j] for j in range(C))
                        + quicksum(cap[i]*u[i]*y[i] for i in range(F)))
```

## 実行:8枚の報告書で決着

```text
反復0: 下界=24818.0, 上界=39429.4, gap=37.06%, 開設=[0,4,5,7,8]
反復1: 下界=36048.5, 上界=39429.4, gap=8.57%
反復2: 下界=37096.2, 上界=39429.4, gap=5.92%
...
反復7: 下界=39429.4, 上界=39429.4, gap=0.00% → 収束!

Benders: 39429.4 / 一括MIP: 39429.4 → 一致
```

![収束](/images/mip-course-5-4-benders/fig1_convergence.png)

分枝限定法(2-2)で見たのと同じ「挟み撃ち」の絵ですが、今回は**カットを1枚足すごとに下界が跳ね上がる**のが特徴です。1枚目の報告書だけでギャップ37%→8.6%。双対価格がいかに情報量の多い「報告書」かがわかります。

面白いのは反復0です。実は**最初の配置 [0,4,5,7,8] が正解**でした(上界が初手から39429.4)。しかし経営者はそれを知る術がなく、以降の7反復は「他の配置はもっと悪い」ことを**証明するため**に費やされています。「見つけるのは早い、証明が残る」——2-3で見たMIP求解の構図が、分解法でも再現されるわけです。

## 鏡写し:列生成とBendersの対応表

第5部の締めくくりとして、2つの分解法を並べます。

| | 列生成(5-1〜5-3) | Benders分解(今回) |
| ---- | ---- | ---- |
| 後から作るもの | **変数**(列) | **制約**(カット) |
| マスターが持つもの | 今ある列だけのLP | 難しい変数 $y$ と見積もり $\eta$ |
| サブ問題の役割 | 儲かる新しい列を探す | 見積もりの嘘を暴くカットを作る |
| サブへ渡す情報 | マスターの**双対価格** | マスターの**解 $\bar{y}$** |
| サブから返る情報 | 新しい列(の係数) | サブの**双対価格**(カットの係数) |
| 終了条件 | 負の被約費用の列が無い | 上界=下界 |
| 効く構造 | 「1リソースの使い方」が列挙不能 | 「決めれば残りがLP」 |

どちらも**LPの双対価格が2つの問題の間を行き来する伝令**になっています。1-4で「双対価格はこの教材の心臓部」と言った理由が、ここで完全に回収されました。

:::message
実務メモを3つ。
- サブ問題が**実行不能**になりうる場合(配置の能力不足など)は、実行不能性を暴く**実行可能性カット**が別途要ります。今回はマスターに「開設能力≥総需要」を最初から入れて回避しました。3-2のスラック方式(人工変数で常に実行可能にする)も定番です
- 今回のようにマスターを毎回ゼロから解き直すのは教材用の実装です。実戦では3-3と同様、**1本の分枝限定木の中でカットを足す**(branch-and-Benders-cut)のが主流で、SCIPならconstraint handlerで組めます
- サブ問題が顧客ごと・シナリオごとに**独立に分かれる**とき(不確実性下の計画など)、Bendersは並列化と相性が抜群です。確率計画法の標準解法(Lシェイプ法)はBendersそのものです
:::

## まとめ

- Benders分解は「**難しい決定を固定すれば残りはLP**」という構造を突く。マスター(整数)+サブ(LP)+見積もり変数 $\eta$
- カットの係数は**サブ問題の双対価格**。強双対性が「どの $y$ に対しても有効な下限」を保証する
- 実測: 8反復で一括MIPと同値の39429.4に収束。1枚目のカットでギャップ37%→8.6%
- 列生成と鏡写し: 変数を作るか、制約を作るか。伝令はどちらも双対価格

これで第5部・列生成法と分枝価格法編は完結です。
