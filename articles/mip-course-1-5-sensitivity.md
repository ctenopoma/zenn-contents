## この記事について

数理最適化を大学1年レベルから列生成法・分枝価格法まで学ぶ教材、第1部・LP編の最終回です。目次はこちら。

@[card](https://zenn.dev/ctenopoma/articles/mip-curriculum-toc)

最適化モデルに入れる数値——需要予測、価格、歩留まり——は、実務では**全部推定値**です。「需要は10個」と入力しても、実際は8個かもしれないし12個かもしれない。ここで必ず聞かれるのがこの質問です。

> 「その"最適"って、**予測が外れても**最適なんですか?」

今回はこの質問に答える道具を3つ、実測で身につけます。

1. **1パラメータのスイープ**: 入力を振って解の動きを目で見る
2. **跳びの観察**: 最適解は連続には動かない。どこで跳ぶかを知る
3. **モンテカルロ・シナリオ分析**: 全パラメータを同時に揺らして、決定の安定性を測る

:::message
コードはすべて手元で実行し、数値・図は実行結果をそのまま貼っています。題材は1-3から使っている3製品の生産計画(最適解 $(4,4,4)$、利益48万円)です。
:::

## 道具1:スイープ 〜 需要上限を振ってみる

製品Bに需要上限 $y \le d$ を追加し、$d$ を0から8まで動かして、それぞれ解き直します。LPは一瞬で解けるので、81回の解き直しは数秒です。

```python
ds = np.linspace(0, 8, 81)
plans = [solve(demand_y=float(d))[1] for d in ds]  # 各needでLPを解き直し
```

![需要上限スイープ](/images/mip-course-1-5-sensitivity/fig1_demand_sweep.png)

読み取れることが3つあります。

- Bが売れない世界($d=0$)では、計画は $(4, 0, 8)$。**Bの生産枠はCに振り替わる**。資源は遊ばせない
- $d$ の増加とともにBが増え、AとCが徐々に譲る。**製品同士の入れ替わり方(トレードオフの構造)**が読める
- $d \ge 4$ で線が全部水平になる。需要上限はもう効いていない(前回の言葉で言えば、この領域で需要制約の双対価格は0)

この図は「需要予測が多少外れたら計画がどう変わるか」への直接の答えです。**予測値1点の最適解だけ見るのではなく、予測が動く範囲で解の地形を見る**——これがスイープの発想です。

## 道具2:跳びの観察 〜 最適解は連続に動かない

次は製品Cの利益係数(販売価格)を2.0〜5.0万円まで振ります。

![利益係数スイープ](/images/mip-course-1-5-sensitivity/fig2_profit_sweep.png)

今度は様子が違います。生産量が滑らかに変わるのではなく、**2箇所で崖のように跳んでいます**。実測ログ:

```text
跳び: c=2.500→2.525 で z=0.00→4.00
跳び: c=3.975→4.000 で z=4.00→8.00
```

- $c < 2.5$: Cは1個も作らない
- $c = 2.5$ を境に、いきなり4個作る計画に切り替わる
- $c = 4.0$ を超えると、Bを全廃してCを8個作る計画に切り替わる

なぜ跳ぶのか。1-1の絵を思い出してください。最適解は実行可能領域の**頂点**にあります。目的関数の傾きが変わると、あるところで「最適な頂点」が**別の頂点に交代**します。頂点から頂点へ、間はありません。だから解は跳びます。

しかも境界の値2.5には見覚えがあるはずです。1-3の単体法ログで、頂点 $(6,4,0)$ における $z$ の被約費用は **+0.5**(利益係数3のとき)でした。つまり係数が $3 - 0.5 = 2.5$ を下回ると $z$ を作る価値が消える。**跳びの位置は被約費用が教えてくれていた**わけです。

実務上の教訓:

- **最適「値」(利益)は連続に動くが、最適「解」(何をするか)は跳ぶ**
- 入力が閾値の近くにいるとき、予測の小さな誤差で計画がガラッと変わる。「先週と今週で計画が全然違う」の原因の多くはこれ
- 計画の激変が業務上困るなら、「前回計画からの変更量にペナルティ」を目的関数に足すのが実務の定石です(第3部のシフト問題で実際にやります)

## 道具3:モンテカルロ・シナリオ分析

実際には需要も価格も資源量も**同時に**ブレます。1パラメータのスイープでは追いきれないので、乱数でシナリオを大量生成して全部解きます。

- 利益係数: ±20%の一様乱数
- 資源量: ±10%の一様乱数
- シナリオ数: 300(LPなので全部解いても数十秒)

```python
for _ in range(300):
    pr = tuple(p * rng.uniform(0.8, 1.2) for p in (5, 4, 3))
    bb = tuple(v * rng.uniform(0.9, 1.1) for v in (24, 32, 20))
    obj, plan = solve(profits=pr, b=bb)
```

![モンテカルロの結果](/images/mip-course-1-5-sensitivity/fig3_montecarlo.png)

```text
利益: 最小38.3 / 中央48.2 / 最大58.5
生産頻度: {'製品A': '100%', '製品B': '95%', '製品C': '86%'}
```

左は「もし各シナリオが実現したら得られる最適利益」の分布。±20%の入力ブレは、利益にして**38〜58万円のレンジ**に化けます。経営への報告は「利益48万円です」ではなく「中央値48、悪くて38、良くて58」と言えるようになります。

右の図がこの回で一番実務的な図です。**「その製品を作る」という決定が、300シナリオ中どれだけの割合で最適解に入っていたか**:

- 製品Aは**100%**。どんなブレ方をしてもAは作る。**迷わず決めてよい**
- 製品Cは**86%**。14%のシナリオではCを作らないほうが良かった。**Cの生産設備に大きな投資をする前には、価格の見通しを固めるべき**

数値の最適解そのものではなく、「**どの決定がブレに対して頑健か**」を報告する。これが不確実性下での最適化レポートの型です。

## 実務メモ:どこまでやるか

- **LPは速い**。解き直しをためらわない。パラメータが不安なら、まずスイープ、次にモンテカルロ。今日の全実験(500回超の求解)は手元で1分未満です
- 双対価格(前回)は「局所の傾き」、スイープは「1方向の地形」、モンテカルロは「全方向のばらつき」。**外側の道具ほど計算は重く、情報は豊か**
- さらに先には、不確実性をモデル自体に組み込む**確率計画法**や**ロバスト最適化**という分野があります。この教材では深入りしませんが、「シナリオ分析で足りなくなったら次に調べる言葉」として覚えておいてください
