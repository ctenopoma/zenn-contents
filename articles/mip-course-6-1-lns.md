## この記事について

数理最適化を大学1年レベルから列生成法・分枝価格法まで学ぶ教材、第6部・最新技術と実務運用編の1本目です。目次はこちら。

@[card](https://zenn.dev/ctenopoma/articles/mip-curriculum-toc)

実務の最適化には締切があります。「毎朝6時までに当日の生産計画を出す」「配車は15分以内に確定」。この世界での問いは「最適か?」ではなく——

> **持ち時間60秒で、どこまで良い解を出せるか?**

今回は同じ問題・同じ60秒で3つの戦略を競争させ、**自作の大規模近傍探索(LNS)がソルバー既定を17.5%上回る**実測をお見せします。

:::message
コードと数値はすべて手元で実行した実測です。
:::

## 題材:証明が絶望的な規模のロットサイジング

3-4の多品目ロットサイジングを、意地悪にスケールさせます。**40品目×48期、しかも期の生産能力が平均需要の1.19倍しかない**(常にカツカツ)。この能力の窮屈さが効いて、SCIPは60秒後もgap **152.9%** という惨状になります。

大事なのはこのgapの読み方です(2-3)。152.9%は「解が悪い」ではなく「**証明が進んでいない**」。下界(dual)側が壊滅しているだけで、解(primal)側の質は別問題です。締切のある実務では、**下界を諦めて primal に全振りする**という選択肢が生まれます。それが今日のテーマです。

## 戦略A:SCIPにそのまま60秒渡す

ベースラインです。2-3で見たとおり、SCIPは内部に丸め系(`r`)・LNS系(`L`)など数十のヒューリスティクスを持ち、実はかなり戦えます。実測では**開始3秒で1,182,949の解**を見つけました。ただし——そこから57秒間、**一歩も改善しませんでした**。分枝限定木が広大すぎて、木の探索からの改善が届かないのです。

## 戦略B:ウォームスタート(そして正直な実測結果)

「前日の計画」や「貪欲法の解」が手元にあるなら、ソルバーに渡せます。今回は「毎期需要ぶんだけ作る」貪欲解(コスト1,579,344)を渡しました。

```python
sol = m.createPartialSol()      # 部分解ヒント(SCIPが補完・検証して受け取る)
for i in range(N):
    for t in range(T):
        m.setSolVal(sol, x[i, t], greedy_plan[i, t])
        m.setSolVal(sol, y[i, t], 1.0 if greedy_plan[i, t] > 0 else 0.0)
m.optimize()
```

結果は……**Aと完全に同じ 1,182,949**。今回のヒントは役に立ちませんでした。理由は明快で、SCIP自身の丸めヒューリスティクスが1秒未満でヒント(1.58M)より良い解(1.27M)を見つけていたからです。

ウォームスタートが効くのは、(1) ソルバーが**実行可能解を見つけること自体に苦労する**問題(複雑なシフトなど)、(2) ヒントがソルバーの初手より本当に良いとき(前日計画+微修正など)。**「渡せば速くなる」ではなく「ソルバーの初手より良い情報か」で判断**します。渡して損はほぼ無いので、良い解が転がっているなら渡す価値はあります。

:::message
`trySol` は求解開始前には呼べない(SCIPのステージ制約)ため、事前に渡すなら `createPartialSol` を使います。実装上ハマりやすいポイントです。
:::

## 戦略C:自作LNS(fix-and-optimize)

本命です。発想は3行で書けます。

1. 手元の解(貪欲でよい)から出発する
2. **大部分を今の値に固定し、一部だけ自由にした小さなMIP**を短時間で解く
3. 改善したら採用して、自由にする場所を変えて繰り返す

「解の近傍を、MIPソルバーの力で探索する」ので大規模**近傍**探索と呼ばれます。今回は「40品目のうちランダムな8品目だけ生産計画を組み直してよい(他は現状のまま)」を近傍にしました。

```python
cur, cur_cost = greedy_plan, greedy_cost
while 残り時間がある:
    free = rng.choice(N, size=8, replace=False)     # 自由にする8品目
    m = build(fixed_plan=cur, free_items=free)      # 残り32品目は現在値に固定
    m.setParam("limits/time", 5)                    # 部分問題は5秒だけ
    m.optimize()
    if 改善した:
        cur, cur_cost = 新しい計画, 新コスト
```

部分問題は変数の8割が固定されているため**5秒で十分よく解けます**。全体の同時最適化は無理でも、「8品目の組み直し」なら SCIP は瞬殺できる——この非対称性を利用するわけです。

## 実測:60秒レース

![60秒レース](/images/mip-course-6-1-lns/fig1_race.png)

| 戦略 | 60秒後のコスト | 貪欲解からの改善 |
| ---- | ---- | ---- |
| A: SCIPそのまま | 1,182,949 | 25.1% |
| B: ウォームスタート | 1,182,949 | 25.1% |
| **C: 自作LNS** | **975,725** | **38.2%** |

読みどころ:

- **AとBは3秒で1.18Mに到達し、以後57秒間フラット**。ソルバーは「見つけるのは速いが、この規模では木の探索から次の改善が来ない」
- **Cは階段状に降り続け**、20秒すぎにA/Bを追い越し、60秒で**17.5%良い解**に到達。しかも12回の部分最適化はどれも5秒以内
- Cの曲線がまだ下向きなことにも注目。時間を伸ばせばまだ降ります(締切次第でスケールする)

## LNSの設計ノブ

fix-and-optimizeを実務に入れるときの調整ポイントです。

| ノブ | 今回の選択 | 調整の方向 |
| ---- | ---- | ---- |
| 近傍の大きさ(自由にする量) | 8/40品目 | 大きいほど1回が強力だが遅い。「部分問題が数秒で解ける最大」を狙う |
| 近傍の選び方 | ランダム | 慣れてきたら「コストの高い品目を優先」「同じ設備を取り合う品目をまとめて」等の**業務知識入り選択**が効く |
| 部分問題の時間制限 | 5秒 | 短すぎると改善せず、長すぎると回数が減る |
| 固定の仕方 | 生産量を固定 | 「段取りの有無(y)だけ固定して量は自由」のような**緩い固定**も有力 |

実はSCIP内蔵のLNS系ヒューリスティクス(RINS、RENSなど、ログの`L`の行)も同じ原理です。内蔵版は問題構造を知らない汎用近傍しか使えないのに対し、**自作LNSは「品目単位で組み直す」という業務構造を近傍にできる**。ここが自作の勝ち筋です。

## 注意:LNSは証明を放棄している

LNSの解には**下界がありません**。975,725が最適から何%離れているかは、LNS単体では永遠にわかりません。実務での賢い併用パターンを2つ:

- **LNSの解をSCIPにウォームスタートで渡して**続きを解かせる。良い上界で木が刈られ、証明側も加速する(戦略BとCの合体)
- 別プロセスで**LP緩和や短時間のSCIP実行から下界だけ取り**、「LNS解は下界から高々◯%」と報告する。gapの言葉(2-3)は保てる

## まとめ

- 締切のある実務では「primalに全振り」が合理的になる局面がある(今回: gap 152%でも解の質は競える)
- ウォームスタートは `createPartialSol`。効くのは「ソルバーの初手より良い情報」のときだけ(実測: 今回は効果ゼロ)
- **fix-and-optimize LNS**: 大部分を固定した小MIPを繰り返す。実測で同じ60秒からSCIP既定比**17.5%改善**
- 設計ノブは近傍の大きさ・選び方・時間制限。**業務知識を近傍設計に入れられる**のが自作の強み
- 証明が要るなら、LNS解をSCIPに返して挟み撃ちを再開する
