## 用語の整理:LP緩和

整数であるべき変数を「一時的に小数もOK」として解いたLPを、元の整数計画の**LP緩和(LP relaxation)**と呼びます。「緩和」=制約を緩めた問題、です。

大事な性質をひとつ。制約を緩めたのだから、**LP緩和の最適値は、真の整数最適値と同じか、それより良い**(最大化なら大きい)。つまりLP緩和は真の答えの**上界**を与えます。この性質は次回の分枝限定法の心臓部になるので、覚えておいてください。

## 実験1:機械の台数決定

工場に機械を導入します。

- 機械A: 利益5万円/台・価格5百万円、機械B: 利益8万円/台・価格9百万円
- 設置スペース: 合計6台まで($x + y \le 6$)
- 予算: 45百万円($5x + 9y \le 45$)

$$\max\ 5x + 8y \quad \text{s.t.}\quad x + y \le 6,\quad 5x + 9y \le 45,\quad x, y \in \mathbb{Z}_{\ge 0}$$

PySCIPOptでは、変数を作るときに `vtype="I"` を渡すだけで整数変数になります。

```python
x = m.addVar("x", vtype="I")   # 整数変数
y = m.addVar("y", vtype="I")
```

まずLP緩和(`vtype="C"`)と整数版をそれぞれ解きます。

```text
LP緩和:   (2.25, 3.75) 利益=41.25
整数最適: (0.0, 5.0)   利益=40.00
```

LP緩和の答えは $(2.25, 3.75)$。「2.25台」は買えないので丸めてみます。

```text
丸め候補 (2, 4): 実行不能!(予算46 > 45)
丸め候補 (3, 4): 実行不能!
丸め候補 (2, 3): 実行可能 利益=34
丸め候補 (3, 3): 実行可能 利益=39
```

図にすると事情が一目でわかります。

![格子点の図](/images/mip-course-2-1-rounding/fig1_lattice.png)

役者を整理します。

- **ピンクの星**: LP緩和の最適解 (2.25, 3.75)。利益41.25万円だが、買えない
- **赤い×**: 四捨五入した (2, 4)。**予算オーバーで実行不能**。丸めは制約を平気で破る
- **オレンジの四角**: 安全側に切り捨てた (2, 3)。実行可能だが利益34万円
- **緑の丸**: 真の整数最適 **(0, 5)、利益40万円**。機械Aを1台も買わない計画

注目すべきは緑の位置です。LP最適の**すぐ隣ではありません**。「LPの答えの近所を探せば整数最適が見つかる」という直感は、一般には成り立たないのです。切り捨て解(34万円)と真の最適(40万円)の差は**18%**。この規模の損失が、「丸めたから」というだけで発生します。

## 実験2:ナップサックでも同じことが起きる

品物12個・容量37のナップサック問題(0/1変数)でも確かめます。LP緩和(各品物を「0.9個だけ積む」ことを許す)を解き、分数になった品物を切り捨てる戦法です。

```text
LP緩和値: 59.73 (品物0だけが分数: 0.909)
切り捨て解: 価値=47(容量27/37しか使えていない)
整数最適:   価値=56
```

![ナップサック比較](/images/mip-course-2-1-rounding/fig2_knapsack.png)

切り捨て解47に対し、真の最適は56。**16%の損失**です。中身を見るともっと面白いことがわかります。

```text
切り捨て解の品物: [5, 7, 8, 9, 10]
整数最適の品物:   [2, 5, 7, 8, 9, 10]
```

LP緩和が「0.909個積め」と言った品物0を、**整数最適は1個も積んでいません**。代わりに、LPでは選ばれなかった品物2が入っています。分数変数を個別に切り上げ/切り捨てして作れる解の中に、最適解がいないケースです。

:::message
なお「切り捨てたあと、余った容量に貪欲に詰め直す」という補修をすれば、この例ではたまたま最適に届きます。丸め+補修は実際、ソルバー内部でも**ヒューリスティクス**として使われている実用的な技です(第6部で扱います)。ただし**最適の保証は決して得られない**——ここが今回の論点です。
:::

## では総当たりすればいいのか?

丸めが駄目なら、整数解を全部列挙して一番良いものを選べばいい。0/1変数が $n$ 個なら候補は $2^n$ 通りです。

![組合せ爆発](/images/mip-course-2-1-rounding/fig3_explosion.png)

- $n=20$: 約100万通り。PCで一瞬
- $n=40$: 約1兆通り。全列挙で数時間
- $n=80$: 約$10^{24}$通り。**宇宙の年齢をかけても終わりません**

シフト表(人×日で数百変数)や配送計画は簡単に $n=1000$ を超えます。総当たりは道具になりません。これが「整数計画はNP困難」と言われることの実務的な意味です——**問題サイズに対して、保証付きで解く時間が爆発的に伸びうる**。

ただし絶望する話ではありません。現代のソルバーは $2^n$ の空間を**証明付きで賢く刈り込む**ことで、数万変数のMIPを日常的に解いています。実際、上のナップサック(候補 $2^{12}=4096$ 通り)をSCIPは一瞬で、しかも「56が最適だ」という証明付きで返しました。

その「賢い刈り込み」の正体が**分枝限定法(Branch and Bound)**です。鍵になるのは、今日出てきた2つの事実です。

1. LP緩和は一瞬で解けて、**上界**(これ以上は稼げない天井)をくれる
2. 実行可能な整数解が1つ見つかれば、それは**下界**(最低でもこれだけ稼げる床)になる

天井と床で挟み撃ちにする——続きは次回。

## まとめ

- 整数変数は `vtype="I"`(整数)/ `vtype="B"`(0/1)を指定するだけ。**ただし解く難しさは質的に変わる**
- LP緩和の丸めは (1) **実行不能になる** (2) **実行可能でも大損する** (3) そもそも**最適解はLP解の近所にいるとは限らない**
- LP緩和の値は真の最適値の**上界**。この性質が次回の主役
- 総当たりは $2^n$ で破綻。ソルバーは証明付きの刈り込みで戦う
