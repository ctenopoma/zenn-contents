## カットとは何か:2次元で見る

前回と同じ機械問題で、1枚のカットが働く瞬間を図にします。

![2Dのカット](/images/mip-course-4-2-cuts/fig1_cut2d.png)

赤い直線 $2x + 3y \le 15$ がカットです。カット(切除平面)と呼ばれるための条件は2つ:

1. **すべての整数実行可能点が満たす**(青い点をひとつも切らない)——これを**妥当不等式**といいます
2. **今のLP最適解(分数)は満たさない**(赤い星を切り落とす)

SCIPで検証しました。

```text
カット前LP: 値41.25, 解(2.25, 3.75)
カット後LP: 値40.00, 解(0, 5)  ← 整数解!
```

このカットを1枚足しただけでLP緩和の最適値は41.25→40となり、整数最適(40)と**完全に一致**。ギャップ3.1%が消滅し、分枝は一切不要になりました。オレンジの多面体が青い整数包へ、1枚ぶんだけ近づいたわけです。

この $2x+3y \le 15$ は、実は整数包の**面(facet)**そのもの——つまり「これ以上強くできない最強のカット」です。2次元なら目で見つけられますが、実際の問題では**今のLP解を切るカットを機械的に見つける**必要があります。この探索を**分離問題(separation problem)**と呼びます。次はそれを手作りします。

## カバー不等式:ナップサックのカットを手作りする

2-2で使った5品のナップサック(重さ [4, 6, 3, 5, 2]、容量10)を再登板させます。

ここで使うカットの族が**カバー不等式**です。論理は単純明快:

> 重さの合計が容量を超える品物の集合 $C$(**カバー**)は、全部同時には積めない。
> よって $\sum_{i \in C} x_i \le |C| - 1$。

例えば品 {0, 1, 2} は重さ 4+6+3=13 > 10 なので、「3つのうち積めるのは高々2つ」。人間には当たり前のこの論理を、LP緩和は知りません(LPは品物を小数で"混ぜられる"ので)。教えてあげるのがカバー不等式です。

分離のループを回します。**LPを解く → 今の分数解が破っているカバーを探す → 見つかったら追加して解き直す**:

```python
while True:
    obj, sol = solve_lp(cuts)
    C = find_violated_cover(sol)   # sum(sol[i] for i in C) > |C|-1 となる極小カバー
    if C is None:
        break
    cuts.append(C)
```

実測ログ:

```text
LP値=25.167, 解=[1.0, 0.167, 1.0, 0.0, 1.0]
  → 違反カバー (0,1,2): x0+x1+x2 <= 2 を追加
LP値=25.000, 解=[1.0, 0.333, 0.667, 0.0, 1.0]
  → 違反カバー (0,1,4): x0+x1+x4 <= 2 を追加
LP値=24.600, 解=[1.0, 0.0, 1.0, 0.2, 1.0]
  → 違反カバー (0,2,3) を追加
LP値=24.571, ...
  → 違反カバー (1,2,4) を追加
LP値=24.462, 解=[0.923, 0.154, 0.923, 0.154, 0.923]
破られているカバー不等式なし → 終了(整数最適は23)
```

![LP値の推移](/images/mip-course-4-2-cuts/fig2_cover.png)

読みどころが3つあります。

- カットを足すたびに上界(天井)が **25.17 → 25.0 → 24.6 → 24.57 → 24.46** と単調に下がる。3-3の遅延制約生成と同じリズムです(あちらは「実行可能性の回復」、こちらは「緩和の強化」が目的)
- 分離のたびにLP解は**別の分数解に逃げる**。カットと分数解のいたちごっこになる
- そして重要なのが最後です。**カバー不等式を出し尽くしても、LP値24.46は整数最適23に届きませんでした**

## カットだけでは終わらない:だから分枝カット法

最後の点が、現代のソルバーの設計思想そのものです。カットには族(カバー、Gomory、クリーク、MIR、…)ごとに得意な形があり、どの族も**それだけでは整数包に到達しきれない**のが普通です。カットの追い足しは回を追うごとに効きが薄くなります(実測でも1枚目0.17改善→4枚目0.11改善)。

そこで、**効きの良いカットを根ノードで打てるだけ打ち、残った隙間は分枝で削る**。これが**分枝カット法(branch-and-cut)**で、SCIPをはじめ現代のMIPソルバーはすべてこの構えです。2-3のログをこの目で読み直すと:

```text
  0.0s| 1 | 0 | ... |cuts | ... | dualbound
  0.0s| 1 | 0 | ... |   1 | ... | 3.207973e+03   ← カット1枚 → 天井が下がる
  0.0s| 1 | 0 | ... |   5 | ... | 3.206407e+03   ← じわじわ
  ...(効きが薄くなったら)...
 59.9s|116300 |     | 3436| ... | 3.191845e+03   ← 以降は分枝の仕事
```

根ノードでdualboundがじりじり下がっていたのは、まさに今日手作りした分離ループをSCIPが何十種類ものカット族で回していた音だったのです。

## 自作カットをSCIPに渡すには

実務で自作カットが欲しくなったら(業務固有の「明らかに無理な組合せ」を知っているときなど)、選択肢は3つあります。

1. **最初から制約として入れる**。カットが少数で事前に列挙できるなら一番簡単。今回のカバー不等式を最初から全部入れる、など
2. **constraint handlerで遅延追加**(3-3でやった方法)。解の候補が出るたびにチェックして `addCons`
3. **Separatorプラグイン**。SCIPのカット分離ループに正式に参加する方法で、分数解に対しても呼ばれます。第6部のプラグイン回で扱います

なおSCIPは自前のカバー不等式分離器(knapsack制約用)を標準装備しています。**自作カットが本当に効くのはソルバーが知らない問題構造を知っているとき**——一般的なカットで済む場面では、ソルバーに任せるのが正解です。

## まとめ

- **カット = 全整数解は守り、今の分数解だけを切る不等式**。良いカットは整数包の面
- カットを探す問題が**分離問題**。カバー不等式なら「重さ超過の集合で、LP解の合計が |C|-1 を超えるもの」
- 実測: カット4枚で上界25.17→24.46。ただし**カットだけでは23に届かない**
- だから**分枝カット法**: 根で打てるだけ打ち、残りは分枝。SCIPのログの `cuts` 列と根ノードのdualbound低下がその現場
- 自作カットの出番は「ソルバーの知らない構造を知っているとき」
