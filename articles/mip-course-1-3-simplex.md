- 単体法 = 「隣の頂点に移ると利益がいくら変わるか」を計算し、得する限り移動する
- その「いくら変わるか」が**被約費用**
- 誰も得しなくなったら、そこが最適(これが最適性の証明になっている)

## 題材:生産計画に製品Cを追加する

1-1の工場に製品Cと組立工程を追加します。

|  | 製品A | 製品B | 製品C | 使える量 |
| ---- | ---- | ---- | ---- | ---- |
| 材料 | 2 kg | 3 kg | 1 kg | 24 kg |
| 機械時間 | 4 h | 2 h | 2 h | 32 h |
| 組立時間 | 1 h | 2 h | 2 h | 20 h |
| 利益 | 5 万円 | 4 万円 | 3 万円 | |

$$\max\ 5x + 4y + 3z \quad \text{s.t.} \quad
\begin{cases}
2x + 3y + z \le 24 \\
4x + 2y + 2z \le 32 \\
x + 2y + 2z \le 20 \\
x, y, z \ge 0
\end{cases}$$

変数が3つなので、実行可能領域は3次元の**多面体**です。頂点を列挙すると8個、辺は12本ありました(コードで列挙しています)。もう「頂点を全部調べる」でも解けますが、変数が1000個になったら頂点は天文学的な数になります。総当たりに代わる賢い歩き方が要ります。

## 単体法のアイデア:得する隣にだけ移動する

単体法の方針は3行で書けます。

1. どこかの頂点から出発する(今回は原点 $(0,0,0)$ = 何も作らない)
2. **隣の頂点**(辺で繋がった頂点)のうち、利益が増える方向があればそこへ移動する
3. どの隣に移っても利益が増えないなら、そこが最適。終了

「隣に移動する」は、変数の言葉で言うと「**今ゼロの変数をひとつ増やし始める**」ことに対応します。原点では $x=y=z=0$。ここから例えば $x$ を増やしていくと、どこかの制約にぶつかって止まります。その止まった場所が隣の頂点です。

## 主役の登場:被約費用

では、どの変数を増やすのが得か。単純に「利益係数が大きい順」ではありません。**すでに資源が埋まっている場合、新しい変数を増やすには他の変数を減らす必要がある**からです。

そこで単体法は各変数について次の量を計算します。

> **被約費用** = その変数を1単位増やしたときの、**調整込みの**利益の変化

「調整込み」がポイントです。具体例で確かめます。単体法が最初の移動を終えて頂点 $(8, 0, 0)$(Aだけ8個、機械32hを使い切り)にいるとします。ここで「Bを1個作り始めたら?」を手で計算すると:

- Bを1個作る: 利益 +4万円。ただし機械が2h必要
- 機械は使い切っているので、**Aを0.5個減らして**機械2hを空ける: 利益 −5×0.5 = −2.5万円
- 差し引き: **+1.5万円** ← これがこの頂点でのBの被約費用

材料はまだ余っているので調整不要(Bの3kgは余りから出せる)。この +1.5 が正である限り、Bを増やす価値があります。

## 実行:4回の反復で最適へ

単体法を教科書どおり実装して(コードは後述)、全反復のログを出しました。

```text
=== 単体法の反復 ===
反復0: 頂点(0.0, 0.0, 0.0) 利益=0.0
   被約費用: {'x': 5.0, 'y': 4.0, 'z': 3.0}
   → x を増やす(s機械 が基底から出る)
反復1: 頂点(8.0, 0.0, 0.0) 利益=40.0
   被約費用: {'y': 1.5, 'z': 0.5, 's機械': -1.25}
   → y を増やす(s材料 が基底から出る)
反復2: 頂点(6.0, 4.0, 0.0) 利益=46.0
   被約費用: {'z': 0.5, 's材料': -0.75, 's機械': -0.875}
   → z を増やす(s組立 が基底から出る)
反復3: 頂点(4.0, 4.0, 4.0) 利益=48.0
   被約費用: {'s材料': -0.5, 's機械': -0.916667, 's組立': -0.333333}
   → 全ての被約費用が0以下。最適!
```

読みどころを3つ。

- **反復0**: 原点では調整が要らないので、被約費用=利益係数そのまま(5, 4, 3)。一番得な $x$ から増やす
- **反復1**: さっき手計算した「Bの被約費用 +1.5」がログに出ています。$y$ の係数は4なのに、調整込みだと1.5まで目減りしている
- **反復3**: 全候補の被約費用が0以下になって停止。これは「**どの変数をどう動かしても利益は増えない」ことの証明**です。単体法は良い解を探すと同時に、最適性の証明書を書きながら歩いています

反復ごとの利益と被約費用の推移です。

![反復の推移](/images/mip-course-1-3-simplex/fig2_iterations.png)

:::details 単体法の実装(タブロー法、約30行)
```python
import numpy as np

def simplex(A, b, c):
    """max c^T x  s.t. Ax <= b, x >= 0 を解く(Dantzig規則)"""
    m, n = A.shape
    # タブロー: [A | I | b] とスラック変数、最下行が目的行
    T = np.zeros((m + 1, n + m + 1))
    T[:m, :n] = A
    T[:m, n:n + m] = np.eye(m)
    T[:m, -1] = b
    T[-1, :n] = -c
    basis = list(range(n, n + m))          # 最初はスラックが基底
    while True:
        rc = -T[-1, :n + m]                # 被約費用
        if all(rc[j] <= 1e-9 for j in range(n + m) if j not in basis):
            break                          # 改善候補なし → 最適
        j = max((jj for jj in range(n + m) if jj not in basis),
                key=lambda jj: rc[jj])     # 被約費用最大の変数を選ぶ
        ratios = [(T[i, -1] / T[i, j], i) for i in range(m) if T[i, j] > 1e-9]
        _, r = min(ratios)                 # 比率テスト: 最初にぶつかる制約
        T[r] /= T[r, j]                    # ピボット(掃き出し)
        for i in range(m + 1):
            if i != r:
                T[i] -= T[i, j] * T[r]
        basis[r] = j
    x = np.zeros(n + m)
    for i, bi in enumerate(basis):
        x[bi] = T[i, -1]
    return x[:n], T[-1, -1]
```
ログに出てくる `s材料` などはスラック変数(制約の余り)です。「スラックを基底から出す」=「その制約を使い切る」と読めます。
:::

SCIPでの答え合わせです。

```text
SCIP: optimal [4.0, 4.0, 4.0] 48.0
```

## なぜ被約費用が列生成の主役になるのか

ログをもう一度見てください。単体法が毎回やっていたのは、

> **「まだ使っていない変数の中から、被約費用が一番良いものを探す」**

でした。今回は変数が3個(+スラック3個)なので全部計算すれば済みます。では変数が**10^11個**あったら? カッティングストック問題のパターン変数がまさにそれです。全変数の被約費用は計算できません。

列生成法のアイデアはこうです——**「被約費用が最良の変数を探す」こと自体を、もうひとつの最適化問題として解く**。全列挙の代わりに、ナップサック問題を1回解けば「次に入れるべき変数」が見つかる。これが第5部でやることの正体で、単体法の「入れる変数を選ぶ」ステップを差し替えているだけなのです。

## 実務メモ:現代のソルバーの中身

- 実際のSCIPが使うLP解法は、この教科書実装より遥かに洗練されています(改訂単体法、疎行列処理、数値安定化)。ただし**構造は今日の話のまま**です
- 単体法と並ぶもう一つの主力が**内点法(バリア法)**。頂点を渡り歩く代わりに領域の内部を突っ切る方式で、超大規模LPではこちらが速いことも多い。ソルバーは問題を見て自動で使い分けます
- 同じ頂点に留まったまま進まない**退化**という現象があり、実務データ(係数が揃いがち)ではよく起きます。ソルバーは対策済みなので通常は意識不要ですが、「LPの反復回数が異様に多い」ときの容疑者として名前だけ覚えておいてください

## まとめ

- 単体法は「得する隣の頂点へ移動」を繰り返す。全頂点は見ない
- **被約費用 = 調整込みの利益変化**。正なら移動する価値がある
- 全変数の被約費用が0以下になったら最適——**探索と証明が同時に終わる**
- 列生成法は「被約費用最良の変数探し」を最適化問題に置き換えたもの(第5部への伏線)
