生産計画の核となる**ロットサイジング問題**を扱います。

> 毎期の需要はわかっている。生産のたびに**段取り費**(ライン切替コスト)がかかる。作り置きすれば**在庫費**がかかる。いつ・どれだけまとめて作るべきか?

「まとめ作りか、こまめ作りか」という、製造業の永遠のトレードオフです。今回の学びは2つ。

1. **在庫バランス制約**——時間のつながりを定式化する型(多期間問題すべての基礎)
2. **同じ問題でも、書き方でLP緩和の質が劇的に変わる**実例。標準形のLPギャップ85.8%が、書き換えで**0%**になります

:::message
コードと数値はすべて手元で実行した実測です。
:::

## 定式化:在庫バランスという型

期 $t = 1, \dots, T$、需要 $d_t$。変数は生産量 $x_t$、期末在庫 $s_t$、段取り $y_t \in \{0,1\}$。

$$s_{t-1} + x_t = d_t + s_t \quad (\forall t)$$

**「前期の在庫+今期の生産=今期の需要+今期末の在庫」**。水槽の水位の式です。この在庫バランス制約は、多期間の問題(生産、資金繰り、人員計画、ダム運用)すべてに現れる**時間をつなぐ定石**です。あとは段取りリンク(2-4のBig-M)と目的関数:

```python
for t in range(T):
    prev = s[t-1] if t > 0 else 0
    m.addCons(prev + x[t] == d[t] + s[t])     # 在庫バランス
    m.addCons(x[t] <= M * y[t])               # 作るなら段取り
m.setObjective(quicksum(f * y[t] + h * s[t] for t in range(T)), "minimize")
```

## 解いてみる:12期の計画

段取り費400円、在庫費2円/個・期、12期のランダム需要で解きます。

```text
最適コスト=2826
生産:     [147, 0, 0, 103, 0, 164, 0, 0, 0, 192, 0, 0]
段取り期: [1, 4, 6, 10]
```

![生産計画](/images/mip-course-3-4-lotsizing/fig1_plan.png)

12期の需要を**4回の段取りでまとめ作り**し、間は在庫で食いつなぐ計画になりました。段取りを増やせば在庫費が減り、減らせば段取り費が減る——その均衡点をソルバーが見つけています。在庫の山が段取りのたびに積み上がっては減っていく、教科書どおりのノコギリ波が出ています。

## 本題:この定式化、実はLP緩和がボロボロ

上の定式化(標準形)のLP緩和を測ってみます。

```text
標準形LP緩和: 400.0 / 整数最適: 2826.0 → LPギャップ 85.8%
```

LP緩和は「コスト400でいける」と主張しますが、真の最適は2826。**86%も楽観的な、ほぼ役に立たない下界**です。原因は2-4で見たBig-Mの病そのもの——$x_t \le M y_t$ の $M$ が総需要(606個)なので、LPは $y_t = x_t/606$ という「段取り費の値引き」を許してしまうのです。

この規模なら一瞬で解けますが、品目と期が増えると、この弱い緩和が刈り込み(2-2)を無力化します。

## 再定式化:facility location形

同じ問題を全く違う変数で書き直します。

> $w_{t,u}$ = 「期 $u$ の需要のうち、期 $t$ に生産して充てる割合」

「どの期の分を、どの期に作るか」を直接決める発想です(施設配置問題と同じ形なのでfacility location形と呼ばれます)。

```python
# 各期の需要は、その期以前のどこかで100%作られる
for u in range(T):
    m.addCons(quicksum(w[t, u] for t in range(u + 1)) == 1)
# 期tに作るなら段取りが要る(需要ごとの個別リンク: 実質M=1)
for t in range(T):
    for u in range(t, T):
        m.addCons(w[t, u] <= y[t])
# 在庫費は「作ってから使うまでの期間」で直接計算
hold = quicksum(h * (u - t) * d[u] * w[t, u] for t in range(T) for u in range(t, T))
```

変数は $T$ 個から $T^2/2$ 個に**増え**、制約も増えます。一見改悪です。ところがLP緩和を測ると:

```text
FL形LP緩和: 2826.0 / 整数最適: 2826.0 → LPギャップ 0.0%
```

**ギャップゼロ。** LPを解いた時点で整数最適値に到達しています(この問題クラスではFL形のLP緩和が常に整数最適値に一致することが知られています)。前回の割当問題で見た「LPだけで解ける」世界に、**書き方の工夫で連れて行った**わけです。

| | 変数の数 | LP緩和値 | LPギャップ |
| ---- | ---- | ---- | ---- |
| 標準形 | $3T$ | 400.0 | 85.8% |
| **FL形** | $T + T^2/2$ | **2826.0** | **0%** |

**「変数と制約が少ないモデル=良いモデル」ではない**。2-4の施設配置に続き、2度目の実証です。

## 実務規模で効果を測る:15品目×24期+能力制約

現実の問題は多品目で、期ごとの生産能力を共有します。能力制約が入るとFL形でもギャップ0にはなりませんが、「緩和を強くする」方向の工夫は効き続けます。今回はもっと手軽な改善——**Big-Mを総需要ではなく「その期以降の残り需要」まで絞る**——で効果を測りました。

```python
# 弱: x[i,t] <= (品目iの総需要) * y[i,t]
# 強: x[i,t] <= min(残り需要, 能力) * y[i,t]   ← 1行の変更
```

15品目×24期、能力制約つき、同一マシンでの実測:

| Big-Mの絞り方 | 求解時間 | ノード数 |
| ---- | ---- | ---- |
| 弱(総需要) | 39.7秒 | 4056 |
| **強(残り需要)** | **14.9秒** | **1374** |

答えはどちらも同じ(コスト82541)。**1行の変更で2.7倍**speedです。「$x_t$ は物理的にどこまで大きくなりうるか?」を考えてMを絞る——ロットサイジングでは「今作った分は将来の需要にしか使えないのだから、残り需要が上限」という業務知識がそのまま高速化になります。

## 実務メモ

- 在庫バランスは多期間モデルの背骨。**書いたら図(在庫のノコギリ波)で検算**する
- 期首在庫・期末在庫の扱い(最終期に在庫を残してよいか)は現場に必ず確認。$s_T = 0$ を入れ忘れると「最終期に大量に作って在庫で終わる」珍解が出ることがあります(今回は在庫費最小化が自然に $s_T=0$ へ導いています)
- 段取りが「切替先に依存」する(品目Aの後にBを作ると洗浄が重い等)場合はTSP的な構造が入り、一段難しくなります。3-3の技が再登場する領域です

## まとめ

- **在庫バランス制約** $s_{t-1} + x_t = d_t + s_t$ が多期間問題の型
- 標準形のLPギャップ**85.8%** → facility location再定式化で**0%**。定式化は変数の数ではなく**緩和の強さ**で選ぶ
- 能力制約つき15品目でも、Big-Mを残り需要で絞る**1行で2.7倍**(実測39.7→14.9秒)
- 「この変数は物理的にいくつまであり得るか」という業務知識が、そのまま計算性能になる
