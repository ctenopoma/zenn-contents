## 準備:バイナリ変数は「命題」である

$y \in \{0,1\}$ のバイナリ変数は「ラインAを動かす」「店舗を出す」のような**真偽が決まる命題**だと思ってください。以下、$y_A$ =「Aをやる」などと読みます。

## パターン集

### 1. 選択の個数(高々1つ / ちょうど1つ / 少なくともk個)

| 日本語 | 不等式 |
| ---- | ---- |
| 候補から高々1つ | $y_1 + y_2 + \cdots + y_n \le 1$ |
| ちょうど1つ選ぶ | $y_1 + \cdots + y_n = 1$ |
| 少なくとも2つ | $y_1 + \cdots + y_n \ge 2$ |

「キャンペーンXとYは併用不可」は $y_X + y_Y \le 1$。もっとも基本の形です。

### 2. 含意(AならばB)

$$y_A \le y_B$$

$y_A=1$ なら $y_B=1$ が強制され、$y_A=0$ なら $y_B$ は自由。「ラインAを動かす(A)ならば検査員を配置(B)」がこの1行になります。**「ならば」が不等号1本になる**——最初は驚きますが、0/1の値を代入して4通り確かめれば納得できます。

| $y_A$ | $y_B$ | $y_A \le y_B$ | 業務的に |
| ---- | ---- | ---- | ---- |
| 0 | 0 | OK | Aやらない、検査員なし。問題なし |
| 0 | 1 | OK | Aやらないが検査員はいる。無駄だが違反ではない |
| 1 | 0 | **違反** | Aやるのに検査員なし。禁止したかった状況 |
| 1 | 1 | OK | Aやって検査員あり |

### 3. 同値(AとBは運命共同体)・排他の応用

- 「AとBは必ずセット」: $y_A = y_B$
- 「AかBの少なくとも一方はやる」: $y_A + y_B \ge 1$
- 「(AまたはB)ならばC」: $y_A \le y_C$ と $y_B \le y_C$ の2本に分解

複雑な論理も、**含意($\le$)・和の上下限の組み合わせに分解**すればたいてい書けます。

### 4. 連続量とのリンク:「作るなら段取り費」(固定費モデル)

ここからが本番です。生産量 $x \ge 0$(連続)と「生産するか」$y \in \{0,1\}$ を連動させたい:

> $x > 0$ ならば $y = 1$(作るなら段取り費 $f \cdot y$ が目的関数に乗る)

これを線形で書く定番が **Big-M法**です。

$$x \le M \cdot y$$

$M$ は「$x$ がとりうる最大値」以上の定数。$y=0$ なら $x \le 0$ に潰れ、$y=1$ なら $x \le M$(実質フリー)。これで「作るのに段取り費を払っていない」状態が禁止されます。

### 5. 逆向きのリンク:「やるなら最低ロット」

$$x \ge L \cdot y$$

$y=1$ なら最低 $L$ は作る。パターン4と組み合わせると「作らないか、作るなら50〜200個」という**半連続変数**になります(後編で深掘り)。

## Big-Mの危険:Mは「嘘の値引き」を生む

Big-M法には有名な落とし穴があります。**Mを大きくするほど、LP緩和が嘘つきになる**のです。

実験します。需要40個、変動費2円/個、段取り費100円、能力60個の生産判断。真の最小コストは $2 \times 40 + 100 = 180$ 円です。LP緩和では $y$ が連続になれるので、$x \le My$ は $y = x/M$ まで「薄める」ことを許します。つまりLP緩和は段取り費を $100 \cdot \frac{40}{M}$ 円しか払いません。Mを変えてLP緩和値を実測すると:

```text
M=60   : LP緩和値=146.7(固定費を33円ぶん値引きして見ている)
M=1000 : LP緩和値= 84.0(96円ぶん値引き)
M=10000: LP緩和値= 80.4(99.6円ぶん値引き=固定費がほぼ消えた)
```

![Big-MとLP緩和](/images/mip-course-2-4-logic/fig1_bigM.png)

LP緩和が嘘をつくほど、分枝限定法の上界(2-2)は当てにならなくなり、刈り込みが効かず、木が育ちます。**Mは「なんとなく1e9」にしてはいけません。その変数の自然な上限(能力、需要合計、営業時間)まで絞るのが鉄則**です。この例なら能力の60が正解です。

## 実測:Mの絞り方ひとつで33倍

もう少し実戦的な例で測ります。施設配置問題(施設60、顧客200)。「顧客 $j$ を施設 $i$ に割り当てる($x_{ij}$)なら施設 $i$ は開いている($y_i$)」というリンクの書き方が2通りあります。

```python
# 弱い書き方: 施設ごとに1本のBig-M(M=顧客数)
m.addCons(quicksum(x[i, j] for j in customers) <= len(customers) * y[i])

# 強い書き方: 顧客ごとに個別リンク(実質 M=1)
for j in customers:
    m.addCons(x[i, j] <= y[i])
```

意味は完全に同じ、答えも同じです。実測結果:

| 書き方 | LP緩和値(小規模例) | 求解時間(施設60×顧客200) |
| ---- | ---- | ---- |
| 弱い(まとめてBig-M) | 2050.8(最適値の54%) | 16.3秒 |
| **強い(個別リンク)** | **3812.9(最適値に一致!)** | **0.5秒** |

強い書き方はLP緩和が**最適値ぴったり**を言い当てており、SCIPはほぼ分枝せずに終わります。弱い書き方は制約本数こそ少ないのに33倍遅い。**「制約は少ないほど速い」は誤解です。効くのは本数ではなく緩和の強さ**——この主題は第4部でとことんやります。

## Big-Mを書かない選択肢:indicator制約

「良いMが見積もれない」場合の逃げ道として、SCIPには**indicator制約**があります。「$y=0$ ならば $x \le 0$」を、Mなしで直接宣言する機能です。

```python
# y=0 のとき x <= 0 を有効にする(activeone=False は「y=0のとき発動」の意)
m.addConsIndicator(x <= 0, binvar=y, activeone=False)
```

実測でも正しく `obj=180, x=40, y=1` が返りました。ソルバー内部で分枝と連動して扱われるため、**巨大なMによる数値トラブルを構造的に回避**できます。トレードオフとして、LP緩和からの情報は限定的になるので万能ではありません。使い分けの目安:

- 自然な上限が見積もれる → **小さいMのBig-M**(LP緩和に情報が乗る)
- 上限が状況依存で見積もれない/Mが巨大になってしまう → **indicator制約**

## まとめ:翻訳チートシート

| 日本語 | 定式化 |
| ---- | ---- |
| 併用不可 | $y_1 + y_2 \le 1$ |
| ちょうど1つ | $\sum y_i = 1$ |
| AならばB | $y_A \le y_B$ |
| AとBはセット | $y_A = y_B$ |
| (AまたはB)ならばC | $y_A \le y_C,\ y_B \le y_C$ |
| 作るなら段取り費 | $x \le M y$($M$は自然な上限まで絞る) |
| やるなら最低ロット | $x \ge L y$ |
| Mが見積もれない | `addConsIndicator` |

- Big-Mの**Mはモデルの品質そのもの**。緩めるほどLP緩和が嘘をつき、実測33倍の速度差になる
- 「制約が少ない=速い」ではない。**LP緩和が強い=速い**
