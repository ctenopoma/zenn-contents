## この記事について

数理最適化を大学1年レベルから列生成法・分枝価格法まで学ぶ教材、第3部・実務の定番問題編の最終回です。目次はこちら。

@[card](https://zenn.dev/ctenopoma/articles/mip-curriculum-toc)

**ビンパッキング問題**——大きさの違う荷物を、容量100の箱に**最少個数の箱**で詰める——を扱います。トラック積載、コンテナ詰め、サーバへのジョブ配置、そして原反切り出し(カッティングストック)がぜんぶこの形です。

この問題は教材の構成上、特別な位置にいます。素直に定式化すると**2つの病気**にかかり、片方は薬(対称性除去)で治るが、もう片方は治らない。その「治らない病」の処方箋こそが**列生成法**(第5部)だからです。今日は2つの病気を実測で確定診断するところまでやります。

:::message
コードと数値はすべて手元で実行した実測です。
:::

## 素直な定式化

荷物 $i$(サイズ $s_i$)、箱 $b$。箱を使うか $y_b$、荷物 $i$ を箱 $b$ に入れるか $x_{ib}$。

$$\min \sum_b y_b \quad \text{s.t.} \quad \sum_b x_{ib} = 1 \ (\forall i), \quad \sum_i s_i x_{ib} \le 100\, y_b \ (\forall b)$$

用意する箱の数は、貪欲法(大きい順に詰めるFFD)の結果で足ります。24個の荷物(サイズ20〜70)でやってみると、FFDは16箱。SCIPで解くと最適も16箱でした。ここまでは平和です。病気は規模を上げると発症します。

## 病1:LP緩和が何も知らない

まずLP緩和値を測ります。

```text
素直な定式化のLP緩和: 12.090
自明な下界(荷物の総量1209 ÷ 容量100): 12.090
```

**完全に一致**。LP緩和は「荷物を液体みたいに注ぎ分ければ12.09箱」としか言っておらず、これは電卓で総量÷容量を計算するのと同じ情報量です。荷物の**組合せの事情**(65と58は同じ箱に入らない、など)を緩和は一切見ていません。真の最適は16箱ですから、下界としての質は最悪です。

2-2を思い出してください。分枝限定法の刈り込みは上下界の挟み撃ちで動きます。下界がこれほど鈍いと、**「15箱で行けるかも」という希望をソルバーはなかなか捨てられず**、証明が延々と終わらない構図になります。

## 病2:対称性 〜 同じ解を何度も数える

もう一つの病はもっと質(たち)が悪い。**箱には個性がありません**。「荷物{0,3}を箱1に、{8,14}を箱2に」と「同じ内容で箱番号だけ入れ替え」は、人間には同じ解です。

![対称性](/images/mip-course-3-5-binpacking/fig1_symmetry.png)

しかし変数 $x_{ib}$ の値としては**別の解**です。16箱の並べ替えは $16! \approx 2 \times 10^{13}$ 通り。探索空間には、実質同じ解がこの倍率でコピーされて浮かんでいます。分枝限定法は「箱3と箱7を入れ替えただけの枝」を律儀に別物として探索し、木が膨張します。

### 実測:対称性の値段

対称性の影響だけを分離するため、「各箱にちょうど3個・ぴったり100」になるよう作った意地悪な36個・最適12箱のインスタンスで、3通りを比較しました。

![対称性処理の比較](/images/mip-course-3-5-binpacking/fig2_compare.png)

| 設定 | 時間 | ノード数 |
| ---- | ---- | ---- |
| 素直な定式化(SCIPの対称性処理を**オフ**) | 58.0秒 | 34,971 |
| 素直な定式化(SCIP既定=**自動対称性処理**) | 6.6秒 | 1,335 |
| **手動の対称性除去制約**を追加 | 4.5秒 | 1,061 |

読みどころ:

- 対称性を放置すると**58秒・3.5万ノード**。これが病気の素顔です
- 実は**SCIPは対称性を自動検出して対処します**(2-3のログにあった `symmetry computation` の行がそれ)。既定のままで9倍速い6.6秒。現代のソルバーはかなり治してくれる
- 古典的な処方箋は**対称性除去制約**を自分で足すことです。今回は2種類入れました:

```python
for b in range(nbins - 1):
    m.addCons(y[b] >= y[b + 1])   # 箱は若い番号から使う
for i in range(len(sizes)):
    for b in range(i + 1, nbins):
        m.addCons(x[i, b] == 0)   # 荷物iは箱0〜iにしか入れない
```

「番号の入れ替えで作れる解のうち、代表1つだけを実行可能に残す」発想です。今回は自動処理より少し速い4.5秒でした。ただし**手動除去はSCIPの自動処理と競合して逆効果になることもあります**(実際、別のインスタンスでは手動追加で遅くなるケースも観測しました)。まず既定で解き、ログの対称性検出を確認し、それでも遅いときに手動除去を試す——が現代の順序です。

## 治らない病:そして「パターン」という発想へ

対称性は治りました。しかし**病1(LP緩和の鈍さ)は対称性除去では1ミリも改善しません**。下界が総量÷容量のままである限り、規模を上げれば必ず「証明が終わらない」壁に当たります。

ここで発想の転換が要ります。原因を振り返ると、変数 $x_{ib}$ が「荷物×箱」という**個性のない組**を表しているのが諸悪の根源でした。ならば——

> 変数を「**箱への詰め方(パターン)そのもの**」にしてしまえばどうか。
> 「{65, 34} を詰める」パターン、「{50, 25, 23} を詰める」パターン……
> 各パターンを何回使うかを変数にすれば、**箱の番号は消え、対称性も消える**。
> しかもLP緩和は組合せの事情(何と何が同居できるか)を最初から知っている。

完璧に見えますが、当然代償があります。**パターンは指数個ある**のです。荷物24種でも、詰め方の組合せは数百万〜数億通り。全部変数にしたらメモリが溶けます。

……この構図、3-3で見ましたね。「制約が指数個 → 破られたものだけ後から足す」。今回は「**変数が指数個 → 必要なものだけ後から作る**」。それを可能にするのが、1-4で仕込んだ**双対価格**と1-3の**被約費用**です。「新しいパターンを1つ作るとしたら、どのパターンが一番得か?」を、双対価格を報酬にした**ナップサック問題**として解く——これが**列生成法**です。

続きは、カッティングストック(原反切り出し)を題材にした列生成法の記事でどうぞ。素直な定式化が120秒でギャップ6.3%を残して敗北し、パターン定式化+列生成が**0.11秒で最適性証明付き**の解を出す実測が待っています。

## まとめ(第3部の総括を兼ねて)

- ビンパッキングの素直な定式化は2つの病気を持つ:**LP緩和が自明な下界と同値**(実測12.09=総量÷容量)、**対称性による探索の重複**(実測: 放置58秒 vs 対策4.5秒)
- 対称性はSCIPの自動処理+手動除去制約でかなり治る。**LP緩和の鈍さは治らない**
- 処方箋は変数の再設計=**パターン定式化**。ただし変数が指数個 → 列生成法(第5部)へ

第3部で扱った5問(割当・シフト・TSP・ロットサイジング・ビンパッキング)で、実務の定番構造はひととおり手に馴染んだはずです。ここから先は2つのルートがあります。

- **目次どおり第4部へ**: 「なぜ同じ問題で速度が1000倍違うのか」——緩和の強さと切除平面を正面から
- **列生成に直行**: 既存の列生成法・分枝価格法の記事(5-1, 5-2)は今日の知識で読めるように書いてあります
